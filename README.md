# Bili Comment Crawler

这是一个完全交互式的 B 站视频评论爬取脚本（当前版本 v3.3.3）。运行后按终端提示依次选择模式、输入参数即可，无需修改代码。

## 功能特性

- 三种模式：全量爬取（一级 + 楼中楼）/ 仅一级评论 / 指定楼层深度爬取
- 三种排序：时间 / 热度 / 回复数
- Wbi 签名鉴权，密钥自动获取并缓存，签名错误自动刷新
- 断点续传：中断后重新运行自动恢复进度
- 楼中楼拉取失败的楼层可交互式重试
- 模式 3 支持树形 / 时间顺序两种展示，可连续爬取多个楼层
- 支持纯 BV 号、完整链接、b23.tv 短链接（自动解析）输入
- **模式 3 支持直接粘贴评论区复制的评论链接**：自动识别 BV 号与楼主 id（root_rpid），步骤 4 直接回车即可确认
- 每次结果同时输出 JSON（完整结构化数据）+ TXT（可读文本）
- 三种速度预设（快速 / 正常 / 慢速）
- Cookie 有效性自动检测并显示登录用户名
- 可选 tqdm 进度条，未安装自动降级

## 环境与安装

- 需要 **Python 3.10+**
- 核心依赖：`pip install requests`
- 可选（进度条）：`pip install requests tqdm`

## 快速上手

```bash
python dlbilicmt.py
```

按提示依次：选择模式 → 粘贴 Cookie → 输入 BVID → 选择排序（模式 1/2）→ 选择速度 → 确认摘要 → 等待完成。结果文件保存在脚本同目录。

> 模式 3 的“输入 BVID”步骤可直接粘贴评论区复制的评论链接（如
> `https://www.bilibili.com/video/BV1kxuw6iEb2?comment_on=1&comment_root_id=309041328033&share_tag=s_i#reply309041328033`），
> 脚本会同时识别出 BV 号与楼主 id。

## 爬取模式

### 模式 1：全量爬取

一级评论 + 所有楼中楼，数据最完整，适合存档与数据分析，耗时最长。

- 阶段 A 拉一级评论：最多 500 页 × 20 条 = 10000 条
- 阶段 B 逐一拉楼中楼：每楼层最多 100 页 × 20 条 = 2000 条
- 拉取失败的楼层可在结束后交互式重试

### 模式 2：仅一级评论

只拉一级评论，速度快。适合快速了解概况、统计用户分布，或查找 `root_rpid` 供模式 3 使用。

### 模式 3：指定楼层深度爬取

输入 `root_rpid` 拉取该楼层全部楼中楼，支持树形 / 时间顺序两种展示。

获取 `root_rpid`（三种方式任选）：

1. **推荐：直接粘贴评论区评论链接**。在 B 站网页端评论区对目标评论点击“复制链接”，在模式 3 的步骤 3 粘贴该链接，脚本自动识别 BV 号与楼主 id；步骤 4 提示“直接回车使用”即可。
2. 先用模式 2 爬取一级评论，在 JSON 中搜索目标用户名，取其 `rpid`（若 `root=0` 即为根评论）。
3. 手动输入纯数字（`root=` / `comment_root_id=` 参数或 `#reply` 锚点后的数字均可）。

链接识别优先级：`comment_root_id=` 参数 → `#reply` 锚点 → 纯数字。

### 展示方式（模式 3）

树形结构：

```
根评论 [用户名] (Lv.6) 2024-01-15 14:30:00
  「这是一条根评论的内容」
  3 条回复
  ├── [用户A] → 回复内容 (14:31:00, 👍5)
  │   └── [用户B] → 对A的回复 (14:32:00, 👍2)
  └── [用户C] → 另一条回复 (14:33:00, 👍3)
```

时间顺序（TXT 中以 `[二级]` / `[三级+]` 标记层级）：

```
根评论 [用户名] (Lv.6) 2024-01-15 14:30:00
  「这是一条根评论的内容」
  --------------------------------------------------
  ├── [二级] [用户A] → 第一条回复 (14:31:00, 👍5)
  ├── [三级+] [用户B] → 回复A (14:32:00, 👍2)
  └── [二级] [用户C] → 另一条回复 (14:33:00, 👍3)
```

## 排序方式

| 选项 | 排序 | 说明 |
|---|---|---|
| 1 | 时间 (sort=0, nohot=1) | 最新在前，翻页上限最高，推荐全量爬取 |
| 2 | 热度 (sort=1, nohot=0) | 点赞最多在前，翻页有上限 |
| 3 | 回复数 (sort=2, nohot=0) | 讨论最热烈在前，翻页有上限 |

热度 / 回复数排序翻页上限较低，选择时会弹确认提示。

## Cookie 获取

需要 B 站登录后的 Cookie，其中 `SESSDATA` 字段必需（有效期约 30 天）。

1. 浏览器登录 bilibili.com
2. F12 → 网络 (Network) → 点击任意请求
3. 复制 Request Headers 中的 Cookie 值
4. 在终端粘贴；多行粘贴时连续按两次回车结束

Cookie 中无 `SESSDATA` 会提示警告；过期后 API 返回 `code=-101`，脚本提示并退出。

## 输出文件

- 模式 1/2：`comments_{BVID}_{排序}_{时间戳}.json` + `.txt`
- 模式 3：`replies_{BVID}_root{rpid}_{tree|flat}_{时间戳}.json` + `.txt`

JSON 结构（模式 1/2）：

```json
{
  "video": {"aid": 123, "bvid": "BV...", "title": "标题"},
  "stats": {"total": 1523, "root": 847, "sub": 676, "users": 523},
  "comments": [
    {
      "rpid": 1234567890, "oid": 123, "root": 0, "parent": 0,
      "uname": "用户名", "uid": "12345678", "level": 6,
      "message": "评论内容", "like": 123, "ctime": 1705312200, "rcount": 5
    }
  ]
}
```

字段说明：

| 字段 | 含义 |
|---|---|
| rpid | 评论唯一 ID |
| oid | 视频 AID |
| root | 根评论 rpid（0 = 一级评论） |
| parent | 被回复评论 rpid（0 = 回复根评论） |
| uname / uid | 用户名 / 用户 UID |
| level | 用户等级（0~6） |
| message | 评论内容（JSON 中始终为完整内容） |
| like | 点赞数 |
| ctime | 发布时间（Unix 时间戳） |
| rcount | 楼中楼回复数（仅一级评论） |

## 断点续传

| 阶段 | 检查点文件 | 保存时机 |
|---|---|---|
| 模式 1/2 拉一级评论 | `checkpoint_{BVID}_root[_only]_{sort}.json` | 每 5 页 |
| 模式 1 拉楼中楼 | `checkpoint_{BVID}_replies_{sort}.json` | 每完成 5 条一级评论 |

- 启动时自动检测并恢复进度
- 完成后自动删除；文件损坏时自动忽略、从头开始
- 按 Ctrl+C 中断时提示检查点已保存，下次运行自动恢复

## FAQ

**Q1: 报错 `No module named 'requests'`**

```bash
pip install requests
```

**Q2: 提示 Cookie 无效或已过期**

重新登录 B 站复制新 Cookie，确认包含 `SESSDATA`。

**Q3: 全量爬取选哪种排序？**

推荐时间排序，翻页上限最高、能拿到最多评论。

**Q4: 如何找 root_rpid？**

最方便的方式：网页端对目标评论点击“复制链接”，模式 3 步骤 3 直接粘贴该链接，脚本自动识别 BV 号与楼主 id，步骤 4 回车确认即可；或先用模式 2 爬一级评论后在 JSON 中搜索用户名，取其 `rpid`；也可手动输入纯数字（支持 `comment_root_id=` 参数、`#reply` 锚点、`root=` 后的数字）。

**Q5: 中断了怎么办？**

直接重新运行，自动从检查点恢复。

**Q6: 评论内容被截断了？**

终端与 TXT 均按"字素簇"安全截断（避免劈开 emoji / 组合字符）：根评论最长 100 字符，树形子回复 50、扁平回复 60，超出加省略号；JSON 的 `message` 字段始终为完整内容。

**Q7: Windows 下颜色显示异常？**

Windows 10+ 的 PowerShell / Windows Terminal / VS Code 终端支持 ANSI 颜色；旧版 cmd 可能不支持，但不影响功能。

**Q8: 模式 3 粘贴评论链接后，步骤 4 还需要输入数字吗？**

不需要。只要链接含 `comment_root_id=` 或 `#reply` 锚点，脚本就会自动提取楼主 id，步骤 4 显示“已从链接识别到楼主id: xxx，直接回车使用”，回车即可。若粘贴的是普通视频链接（无评论参数），则需手动输入数字。

## 技术细节

| 项目 | 说明 |
|---|---|
| API 端点 | `/x/v2/reply`、`/x/v2/reply/reply`、`/x/v2/reply/detail`、`/x/web-interface/nav`、`/x/web-interface/view` |
| 认证方式 | Wbi 签名（w_rid + wts）+ Cookie（SESSDATA） |
| 一级评论上限 | 500 页 × 20 条 = 10000 条 |
| 楼中楼上限 | 100 页 × 20 条 = 2000 条/楼层 |
| 评论链接解析 | `comment_root_id=` 参数 → `#reply` 锚点 → 纯数字，均自动提取 root_rpid |
| Wbi 密钥 | 缓存在 session 对象上，签名错误（-412）时自动刷新 |
| tqdm | 可选依赖，未安装自动降级为无进度条 |
